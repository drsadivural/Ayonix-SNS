# 6. UI and design acceptance

Use design/index.html, deterministic PNG screens, design-overview.pdf and optional concept boards. Exact requirements and accessible code override any generated-text defect in a concept image. These are design previews with example data; production must never import their example metrics. Typography: Inter or a locally served equivalent, 14–16px body, 12px minimum metadata. Azure #176BFF, navy #10233F, canvas #F5F8FC, white cards, 12–16px radii, restrained shadows. Light and dark themes, system preference and stored manual choice. Desktop 1440×1000, tablet 834×1112, mobile 390×844. Minimum 44px touch targets, visible keyboard focus, labels, accessible chart summaries and contrast verification.

## Exactly five menus

| Menu | Required content and actions |
|---|---|
| Dashboard | Product/date/channel filters; quota indicator; published, scheduled, available impressions and engagement; real time-series chart; channel breakdown; upcoming queue/calendar toggle; new schedule drawer; pending approval/error rows; expand details and actual post link |
| Connectors | ChatGPT connection status/instructions; LinkedIn, Facebook, Instagram, TikTok, YouTube cards; actual account and capability; Connect, Reconnect, Disconnect; approval/read-only warning; scoped OAuth consent |
| Billings | Current subscription and next invoice; Basic/Standard/Premium/Custom cards; custom calculator; change-plan effective date; Stripe Checkout/Portal; invoices; payment failure/canceled/expired states |
| Reports | Product/date/channel filters; accessible metric charts; data freshness; best posts; source definitions; compare periods; real CSV/PDF generation with download and signed expiry |
| Settings | Workspace; Products; Members; Events; Security; notification preferences; locale/timezone; deletion/export. Internal tabs only, no extra top-level navigation |

Dashboard tabs may contain Schedule and Analytics; don't add a top-level Calendar, Media, Products, AI Studio, Campaigns, Logs or Admin. Upload lives inside composer; product profiles inside Settings; privileged platform operations are separate staff access, not a sixth customer menu.

## Supporting screens

1. Independent website register/login: email verification or approved OIDC, password reset through auth provider, terms/privacy, recoverable validation and email failure states.
2. Website onboarding: Account → Plan → Channels; skip connector configuration without implying successful publishing. Stripe return remains pending until webhook confirmation. Trial is independently offered on the website only.
3. MCP consent: requested scopes and workspace selection; sign in to existing account, approve/deny. No plans, checkout or required-purchase step.
4. Schedule drawer: product, account targets, per-network content, owned assets, preview, exact local/UTC times, quota cost, approvals, save draft and confirm schedule. Unsupported target format explains what must change.
5. TikTok approval sheet: fetched account identity, preview, editable title, privacy choice, interaction settings, commercial declarations and required consent. No default privacy. Reject stale creator constraints.
6. Target details: draft/approval/scheduled/queued/uploading/processing/published/retry/reconnect/failed/unknown/canceled state, next action, redacted error, exact provider receipt if available.
7. Mobile dashboard: collapsed header, five-item accessible navigation, single-column cards, readable chart and queue, full-height composer. No horizontal page overflow.
8. Dark dashboard: identical data/actions and hierarchy, independently checked chart and text contrast.

## Every page must handle

Loading, empty, permission denied, real error, retrying, stale data, disconnected, quota exceeded, suspended billing and narrow screen. First-time dashboard says “Connect a channel” with an actual action. Unavailable metric says “Not available”; zero is used only for a real measured zero. Icons cannot be the sole status cue. Published requires provider confirmation. Use short labels; technical API details stay in expandable diagnostic events.
