# 8. Claude Code implementation order

Each milestone requires implementation, applicable tests and persisted evidence. A plan or screenshots cannot close a milestone. When one external dependency is blocked, complete independent work and return to that gate.

1. **Baseline and preflight.** Inspect repository/instructions, actual runtime/network, git diff, current deployment/auth and existing work. Execute package tests. Read all docs/contracts, inventory accounts without revealing secrets. Create docs/decisions with actual versions and current provider/policy findings. Output requirement matrix with all production gates initially BLOCKED.
2. **Project foundation.** Create the target structure, TypeScript strict config, Vite React app, Worker routes, local D1/R2/queue bindings, schema migrations, structured logs, security headers, config validation and CI. Install/pin dependencies and lockfile. CI runs typecheck, lint, unit/integration tests, migrations and build. CI does not publish customer posts.
3. **Identity and tenancy.** Implement maintained auth, registration, verification, reset, session termination, workspace creation, memberships/invites/roles and tenant isolation. Integrate MCP-capable OAuth provider and prove its discovery/PKCE independently. Test malicious IDs, CSRF, wrong audience and last-owner protection.
4. **Commercial rules.** Incorporate tested pricing/domain rules into shared package. Implement subscriptions, server quotes, Stripe sandbox Checkout/Portal, raw-body signature checking and deduplication. Prove initial payment, declined card, renewal, reordered events, cancellation and downgrade. Implement trial/cycle quotas and concurrency tests against real database, not just pure arithmetic.
5. **Media and products.** Implement profiles, sources/claims, uploads, R2 lifecycle, media validation, signed downloads and SSRF prevention. Draft persistence survives refresh and restart. Implement research/learning using real licensed APIs, sources/citations, caps, audit and review. No successful empty results substituted for failed requests.
6. **Connector lifecycle.** Build one adapter at a time; complete OAuth, discovery, capability, upload, publish, poll, metrics and disconnect. Start LinkedIn/Facebook/Instagram, then TikTok/YouTube, subject to approval availability. Use authorized dedicated test accounts. Record actual IDs and test format matrix. UI cannot mark pending-review capability as available.
7. **Scheduling engine.** Implement version-bound previews/approvals, atomic quota/outbox, coordinator, leases, cron/queues, reconciliation, retries, DLQ, cancellation and native scheduling ownership. Inject crash after remote creation and before local receipt; prove no blind duplicate submission. Prove target status after conversation/process closure and deploy restart.
8. **Customer UI.** Build all five menus and supporting flows from design source; wire every action to real APIs. Replace all example values with API results and empty/unavailable states. Implement desktop/tablet/mobile light/dark. Add accessible chart tables, event drawer, reports download, notifications and privacy flows. Verify the exact custom-price max.
9. **ChatGPT MCP.** Register real tool schemas, auth scopes, read/write hints, error challenges and signed preview flow. Test in ChatGPT with the actual remote endpoint. Prove create → preview → confirm → durable dispatch → provider receipt → report, plus cancel/reconnect/wrong-tenant/duplicate cases. Respect digital-commerce restriction; no checkout tool.
10. **Operational hardening.** Implement SLO monitoring, safe alerts, rate limits, backups, restore, key rotation, retention and deletion/export. Verify queue redrive, database recovery, deployment rollback and zero secret leakage in logs. Complete cost/load tests against scoped staging resources; no live posting storm.
11. **Release verification.** Execute every mandatory acceptance case. Capture browser runtime screenshots and errors. Run production build/typecheck/lint. Deploy staging, smoke-test real callback/MCP/signatures, verify deployed schema and assets. Review scope/security. Prepare production release and migration/rollback commands against actual resource IDs; no placeholder deployment commands.
12. **External review and release.** Prepare submission documents/video/test access. Provider review and ChatGPT directory acceptance are external gates. Do not label the full request COMPLETE if the install-to-payment requirement remains blocked or any claimed network cannot publish. Provide a concrete reviewable release with exact limitations and operator actions. Production deployment/publication/charges follow actual authorization.

At each milestone save an evidence JSON row: requirement ID, status, environment, timestamp, commit SHA when available, command/request, exit code, safe artifact path, actual expected/observed result and blocker. Never generate fake evidence dates, checksums, URLs, test passes or post IDs. Review source and runtime results before changing status.
